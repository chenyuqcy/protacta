## Earlier external blocker audit

All three engineering phases queried the device inventory. The saved JSON in
`output/first-fold/available-devices.json`, `output/full-course/devices.json` and
`output/validation-capture/devices.json` reports the paired iOS devices' tunnel
state as **unavailable**. That state was queried again during Build 3. These
are terminal inventory queries, not a live install or camera job to wait on.

The first two phases made software progress despite this condition. The current
phase repaired checker defects and completed the concrete local evidence tools.
Remaining required acceptance now needs an actual connected/unlocked device,
physical paper handling/review, independent human annotations and beginner
participants. More simulated frames cannot establish those requirements.

## User-directed local continuation: 25 October 2026

The user answered: “先继续本地开发，稍后真机测试”. Build 4 therefore added a
frozen, same-frame visual comparison with temporary memory-only images,
action-specific draft guidance, same-action 3D replay and lifecycle invalidation.

This meaningful local progress does not satisfy the physical acceptance rows.

AERIS manual. Build 5 implements their native teaching flows while retaining the
original physical acceptance requirements. New courses are authored illustrations
and manual comparisons, not additional calibrated camera graders. The user chose
to defer cloud AI. See INTEGRATION_BUILD_5.md for current validation/installation.

network; installed version and a running process were queried independently.
DEVICE_INSTALL_2026-10-25.md records this new gate. Physical camera/folding
behavior and learning outcomes remain unverified.
